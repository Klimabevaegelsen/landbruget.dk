# Pesticide allocation

`pesticide_disaggregation.py` turns SJI pesticide reports from company level
into estimated field-level allocations. It is an allocation model, not a record
of observed spraying on a particular field.

## Input and period

For pesticide year `YYYY`, the job reads:

- `silver/pesticides/.../pesticiddata_YYYY_YYYY+1.parquet`
- `silver/fvm_marker_YYYY+1/.../data.parquet`

The SJI year is the first year of the agricultural reporting period: `2015`
means 1 August 2015–31 July 2016. The job uses field data from `YYYY+1`, so
the result is a field representation from the following year, not a
simultaneous field observation.

## Allocation rules

The job requires a normalized CVR number, crop code, and a positive reported
area. It does not substitute a broader crop group, a nearby field, or a field
from another year.

1. For farms with organic and non-organic fields of the same crop, compare the
   total area with and without the organic fields and use the eligible result
   with the smallest area difference.
2. For the remaining records, match the reported area to the total area of the
   farm's fields with the same crop.
3. Retry remaining records after excluding organic fields.
4. If the farm has exactly one field of that crop and the reported area is
   smaller than the field, allocate the report to that field as a partial-field
   allocation.

The usual area comparison has a 2% tolerance. For a multi-field allocation,
both quantity and cumulative treated area are divided in proportion to field
area. This gives every allocated field the same period-average reported rate;
it does not establish where or when individual spray passes occurred.

Records that do not meet one of these rules are not emitted as field
allocations. Changes in field boundary, field identifier, or operator between
the two years are not separately reconstructed.

## Historical limitation

In the production run verified on 1 July 2026, the paired FVM 2015 data had no
numeric CVR values. The current CVR-and-crop method therefore allocated no
2014 SJI rows.

## Output and coverage

Output is written as one or more allocation rows per SJI record. Important
columns include `field_uuid`, `AllocatedArea`, `DosageQuantity`,
`AllocationMethod`, `MatchConfidence`, and `IsPartialFieldCoverage`.

The reproducible validation script can inspect a year, but record coverage
must be calculated from the raw SJI input and the resulting allocations for
the same run. It is not the share of original kg or litres allocated. The
published quality files do not yet contain a quantity-weighted coverage
measure or an unallocated-quantity breakdown.

For the full, run-dated production snapshot and the exact validation
behaviour, see [the pipeline documentation](../../../docs/pesticide_disaggregation_gold.md).

## Run and validate

From `backend/pipelines/unified_pipeline/src`:

```bash
uv run python -m unified_pipeline run \
  --source pesticide_disaggregation \
  --stage gold \
  --pesticide-year 2021
```

Omit `--pesticide-year` to process every available pesticide year. Validate a
year from `backend` with:

```bash
uv run python scripts/validate_disaggregation_robustness.py \
  --year 2021 --analysis all --verbose
```

The public dataset README is generated by
`backend/pipelines/api_export/exporters/pesticide_bulk_dataset.py`.
